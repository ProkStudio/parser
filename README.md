# Parser 0.2 — аккаунты, прокси, задачи

Локальное приложение для чтения сообщений доступных вам Telegram-каналов и групп. Теперь **по умолчанию открывается отдельное окно**, не вкладка браузера. Интерфейс использует системный WebView: на Windows — Edge WebView2.

> Предварительная версия. Живой вход и сбор с настоящим Telegram-аккаунтом нужно проверить на вашем компьютере. Автотесты используют только синтетические ключи и сообщения. Файлы `.session`, `tdata`, API-ключи и пароли никому не отправляйте и не коммитьте в GitHub.

## Запуск из исходников — Windows

Нужен Python 3.11–3.13 x64 и [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/). Установка Python не нужна для готовой MSI-сборки, если она доступна в Actions.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install ".[desktop,tdata]"
.\.venv\Scripts\python -m parser_app
```

Если у вас другая поддерживаемая версия Python, замените `py -3.12` на `py`.

Также можно запустить `start-windows.bat` из распакованной папки: при первом запуске он создаёт `.venv` и устанавливает зависимости. Нужен интернет для первой установки. Сам парсер открывается отдельным окном.

**Старая MSI 0.1.0 не содержит эти изменения.** Новая ветка не сливается в `main` автоматически. Сборки этой версии смотрите в GitHub Actions → Build and verify Parser → Parser-Windows-x64. Публикация нового релиза выполняется отдельно после проверки.

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install '.[desktop,tdata]'
python -m parser_app
```

На Linux дополнительно нужны графическая сессия и зависимости Qt/GTK для pywebview, например `pip install 'pywebview[qt]==6.2.1'`. На macOS используется системный WebKit. Нативные сборки Linux/macOS не подготовлены. Windows — основной целевой вариант.

## 1. Аккаунты

**Аккаунты → Добавить аккаунт** предлагает три способа.

### Файлы `.session`

1. Закройте программу, которая использует эти сессии.
2. Выберите `.session` в окне добавления.
3. Введите API ID и API Hash приложения, с которым создавались сессии: эти значения не хранятся в самом `.session`.
4. Нажмите **Выбрать файлы .session**, выберите один или несколько файлов в системном диалоге (до 50 за раз).
5. Прочитайте результат для каждого файла. Дубликаты не создаются; ошибка одного файла не отменяет остальные.
6. Закройте окно импорта. При необходимости назначьте прокси через **Настройки** в строке аккаунта. Нажмите **Проверить**.

Поддерживается **Telethon SQLite `.session`**, размер до 32 МБ. Не поддерживаются Pyrogram, StringSession, ZIP и файлы с произвольно изменённым расширением. При активном SQLite-журнале сначала закройте исходную программу: вручную удалять `-wal`/`-journal` нельзя.

Импорт читает исходный файл без записи и создаёт новую локальную базу с записью авторизации. Контакты, произвольные SQL-объекты и сохранённые серверные адреса из файла не переносятся. Соединение выполняется только с известным production DC Telegram. Перечень диалогов при необходимости запрашивается после подключения к Telegram.

### Папка `tdata` — экспериментально

1. Полностью закройте Telegram Desktop, включая значок в системном трее.
2. Если у вас ZIP, сначала распакуйте его обычным архиватором.
3. Выберите **tdata**. Если в Telegram Desktop установлен локальный код-пароль блокировки, введите его. Это не облачный пароль 2FA; без локального кода поле оставьте пустым.
4. Нажмите **Выбрать папку tdata** и выберите саму папку с `key_data`/`key_datas`. Обычно это `%APPDATA%\Telegram Desktop\tdata`. Выбирать родительскую папку Telegram Desktop не нужно.
5. Доступные библиотеке аккаунты из папки добавляются отдельно. Нажмите **Проверить** у нужного аккаунта.

Конвертация выполняется **локально в отдельном процессе**, без загрузки файлов в интернет, QR-логина и автоматического подключения к Telegram. Локальный код-пароль не сохраняется. Используются параметры исходного Telegram Desktop; вручную вводить API-ключи для tdata не нужно.

Чтение выполняет `opentele==1.15.1`. [Автор opentele больше не поддерживает проект](https://github.com/thedemons/opentele#notice), поэтому совместимость с новыми форматами Telegram Desktop не гарантируется. При ошибке программа предлагает вход по номеру — не обход кода-пароля и не отключение 2FA.

### Вход по номеру

**Добавить аккаунт → По номеру → Продолжить**. Получите API ID/API Hash на [my.telegram.org](https://my.telegram.org), затем введите номер, код из Telegram и, если требуется, облачный пароль 2FA. Коды и пароль не сохраняются. Настроить незавершённый аккаунт повторно можно через **Настройки → Войти / настроить**.

### Важно о сессиях

- Импортированная копия **переиспользует ту же авторизацию**, что и оригинал. Это не новая независимая сессия Telegram.
- Не запускайте одну и ту же авторизацию одновременно на разных устройствах/IP: Telegram может отозвать её. Для независимого доступа предпочтителен новый вход по номеру.
- **Удалить из Parser** удаляет локальную копию, но не исходный файл и не авторизацию в Telegram. Сообщения сохраняются, задачи удалённого аккаунта больше нельзя продолжить.
- Для отзыва доступа используйте Telegram → Настройки → Устройства. Это может отключить и исходное приложение.
- Сессии и настройки — конфиденциальные локальные файлы, не зашифрованное хранилище. На Windows они наследуют права папки текущего пользователя, на POSIX создаются с ограниченными правами. Используйте шифрование диска и защищённую учётную запись ОС. Локальное удаление не обещает безопасное стирание с SSD/резервных копий.

## 2. Прокси

**Прокси → Добавить прокси**: название, SOCKS5 или HTTP CONNECT, адрес, порт, необязательные логин и пароль. Затем **Аккаунты → Настройки → Прокси для аккаунта → Применить → Проверить**.

- Прокси необязателен. MTProto-прокси пока не поддерживаются.
- Проверка прокси — TCP-туннель до Telegram, а не авторизация аккаунта и не гарантия стабильности соединения.
- Назначенный недоступный прокси **не заменяется прямым соединением**. Ротации прокси и обхода лимитов нет.
- Пароль хранится только локально; список прокси не возвращает его в интерфейс.
- Изменять привязки и удалять аккаунты/прокси можно только после паузы или отмены активных задач.

## 3. Задачи

**Задачи → Новая задача** → проверенный аккаунт → источники. Дополнительные поля спрятаны в **Фильтры и лимиты**: период UTC, фразы включения/исключения, тип сообщений, лимит просмотра, продолжение с позиции аккаунта.

- Поддерживаются `@username`, `https://t.me/channel` и доступные приватные группы по `-100…` ID. Автоматического вступления по приглашениям и обхода доступа нет.
- У задачи закреплён аккаунт. Выбор другого аккаунта в интерфейсе её не переключает. Курсоры продолжения раздельны для аккаунтов.
- Одна последовательная очередь. Нет параллельных сборов или переключения аккаунтов для обхода FloodWait. Ожидание лимита консервативно применяется ко всей очереди и переживает перезапуск.
- Пауза/отмена сохраняют сообщения. Закрытие окна сохраняет текущий сбор на паузе. После запуска нажмите **Продолжить**.
- **Результаты** в этой же вкладке: поиск, выбор источника, страницы, экспорт CSV/JSON/JSONL через системное окно сохранения. CSV защищается от формул в тексте сообщений.
- База результатов общая для аккаунтов пользователя ОС; дубликаты сообщений одного канала не размножаются.
- Приложение читает тексты и метаданные сообщений. Оно не выгружает телефоны участников, не рассылает сообщения и не скачивает бинарные медиа.

## Данные и обновление

Windows: `%LOCALAPPDATA%\Parser`; Linux: `$XDG_DATA_HOME/parser` или `~/.local/share/parser`; macOS: `~/Library/Application Support/Parser`.

Прежний аккаунт `telegram.session`/`config.json` обнаруживается автоматически без перезаписи файлов. Старые задачи остаются привязаны к нему, а не к новому выбранному аккаунту. База мигрирует на схему v2 для раздельных курсоров. **Перед обновлением сделайте приватную резервную копию папки данных; не запускайте 0.1.0 поверх обновлённой базы.** Удаление программы не удаляет личные данные.

## Для разработки

```bash
python -m unittest discover -s tests -v
python -m compileall -q parser_app
node tests/browser.mjs
```

Для browser-тестов нужен Playwright (`npm install --no-save playwright@1.51.1`; `npx playwright install chromium`). Генерируются синтетические UI-снимки в `.qa/`, не пользовательские сессии. Проверяются три вкладки, оба пути импорта через имитацию системного диалога, локальный импорт SQLite, привязки, вход/2FA, задача, пауза/отмена, поиск/экспорт, XSS и ширина 390 px. Настоящий мост окна дополнительно проверяется `--window-smoke` в Windows CI.

`python -m parser_app --browser` — явный режим браузера без импорта сессий. `--no-browser` — headless API для разработки; закрывайте процесс самостоятельно. В обычном запуске этих флагов нет, автоматического перехода в браузер при ошибке WebView не происходит.

## Что посмотрели на GitHub

- [Grigorich-JSDio/TG-Parser](https://github.com/Grigorich-JSDio/TG-Parser): консольная выгрузка участников/истории через Telethon, не готовый интерфейс с тремя вкладками. Код не копировался.
- [RozittaParser](https://github.com/Nynchezyabka/RozittaParser): готовая альтернативная настольная программа для архивирования чатов; README заявляет tdata и прокси. Это отдельный продукт с другим интерфейсом, его бинарные сборки здесь не проверялись. Заявления сторонних авторов о гарантии отсутствия блокировок не являются гарантией Telegram.
- [opentele](https://github.com/thedemons/opentele): локальное чтение tdata; ограничение поддержки указано выше.
- [pywebview](https://github.com/r0x0r/pywebview): системное окно поверх существующего локального интерфейса, без переписывания надёжной очереди и базы.

Зависимости сохраняют собственные лицензии. В частности, дополнительный модуль tdata использует PyQt5 (GPL/commercial); перед распространением собранных бинарных версий проверьте лицензионные требования. Изменения не назначают новую лицензию вашему репозиторию и не публикуют новый релиз автоматически.
